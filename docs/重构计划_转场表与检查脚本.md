## 准备：做一份基线

重构前先在两个项目上把输出存下来，后面每一步都拿它对比：

```bash
# 项目 A：examples/yuai/project（单段，start=0）
# 项目 B：任意一个接力分段项目（start≠0），没有的话把 A 的 plan.json start/end 各加 240 帧复制一份
```

### 现在的问题

| 位置 | 内容 |
|---|---|
| `kit/engine/relay.js` 约 943–946 行 | `MODES`（模式名 → 着色器编号）、`KIND`（模式名 → 登记的 kind） |
| `kit/tools/songmv/trans_check.py` 约 31–37 行 | `KINDS`（kind 中文名）、`LIGHT_MV`、`LIGHT_KIND`；T8 里写死的方向性模式 `('whip','split','occlude','leak')` |

### 各处怎么改

1. **relay.js**：删掉 `MODES` 和 `KIND` 两个字面量。在 `run()` 开头读 moves.json 的地方，照同样写法读这张表：
   ```js
   try { TRANS = await (await fetch('engine/transitions.json')).json(); } catch (err) { TRANS = TRANS_FALLBACK; }
   ```
   `MODES[name]` 改成 `TRANS.modes[name]?.shader`，`KIND[k.mode]` 改成 `TRANS.modes[k.mode]?.kind`。
   注意：`MODES` 现在是 `export const`。先 `grep -rn "MODES" kit` 查有没有别处 import 它；有的话保留一个导出（比如 `export function modeId(name)`）。
   `TRANS_FALLBACK` 留一份最小内联表，让 fetch 失败的老项目也能渲染。
2. **新建 `kit/tools/transitions.py`**（Python 端的读取器，参照 `dance.py` 的 `load_moves`）：
   ```python
   def load(root='.') -> dict           # 读 <root>/engine/transitions.json，找不到就读 kit 自带那份
   def weight(entry, T, mv_at=None) -> 'light'|'heavy'   # 先看 entry['mv']，再看 mv_at 找回的模式名，最后按 kind 兜底；拿不准算 heavy
   def directional(mv, T) -> bool
   def eye(mv, entry, T) -> int         # whip 固定 +1，其余看 entry['dir']，缺省 +1
   def kind_names(T) -> dict
   def draft_cycle(T) -> (heavy_list, light_list)
   ```
3. **trans_check.py**：`KINDS`、`LIGHT_MV`、`LIGHT_KIND`、`weight()`，以及 T8 的方向性模式元组和 `eye` lambda，全部换成 `transitions.py` 的函数。
4. **camplan.py**：`heavy_cycle` / `light_cycle` 改用 `draft_cycle(T)`；落色只放尾奏改成看 `calm_only`。
5. **references/engine.md**：轻/重表保留（给人看的），加一句“以 `engine/transitions.json` 为准”。可选：加个小脚本 `kit/tools/gen_trans_table.py`，从 json 生成这张表，避免两边写得不一样。

### 验收

- `grep -rn "LIGHT_MV\|LIGHT_KIND\|heavy_cycle\|light_cycle" kit` 搜不到任何结果。relay.js 里也不再有模式名 → 编号的字面量（`TRANS_FALLBACK` 除外）。
- 项目 A 和 B 重跑 `trans` 和 `camplan`，跟基线 diff 没有差异（`diff out/trans_check.md out/trans_check.base.md`）。
- `python tools/run.py still 10 20` 能正常出图，说明 relay 读表成功，转场着色器编号也没错。再把 `engine/transitions.json` 临时改名，确认还能出图（走的是 fallback）。
- 新建项目（`new_project.py`）和 `run.py upgrade-engine` 之后，项目的 `engine/` 里都有 `transitions.json`。

## R2 trans_check.py 拆成“一条规则一个函数”

### 现在的问题

`kit/tools/songmv/trans_check.py` 有 221 行，几乎全写在模块顶层（只有 `weight`、`in_calm` 两个函数）。每条规则写了三遍：判断逻辑、`out.append(...)` 里的英文 md 行、`RULES` 里的中文 detail。三处已经开始对不上（T7 修之前，说明写的是“桥段可以”，代码却会报）。另外：

- 有两处 `__import__('itertools')`
- T8 在循环里定义 lambda，每条转场都要对全部帧做一次 `min`
- 读 json 一部分用了 with，一部分还是裸的 `open()`

### 改成

```python
# kit/tools/songmv/trans_check.py
import itertools
from dataclasses import dataclass

@dataclass
class Ctx:                    # 一次读齐，规则函数只读不写
    P: str; mode: str; TR: list; L: list; TL: dict; grid: 'np.ndarray'; drops: list
    plan: dict; parts: list; vox: dict | None; T: dict   # T = transitions.load()
    fr: 'np.ndarray | None'   # 成片帧（没给成片为 None）

@dataclass
class Result:
    rule: str; name: str; ok: bool; detail: str; md: str   # md = 给 trans_check.md 的那一行

def load_ctx(argv) -> Ctx: ...
def rule_T1(c: Ctx) -> Result: ...
def rule_T2(c) -> Result: ...
...
def rule_T8(c) -> Result: ...
RULE_FUNCS = [rule_T1, rule_T2, rule_T3, rule_T4, rule_T5, rule_T6, rule_T7, rule_T8]

def main(argv=None) -> int:
    c = load_ctx(argv or sys.argv[1:])
    if not c.TR: return no_transitions(c)        # 现在“没登记 TRANSITIONS”那段早退
    res = [f(c) for f in RULE_FUNCS]
    write_md(c, res); write_json(c, res)
    return CC.exit_code([r.__dict__ | {'tier': CC.tier(r.rule)} for r in res])

if __name__ == '__main__': sys.exit(main())
```

要点：

- 每条规则的说明只写一份：`detail`（中文）和 `md`（报告行）在同一个函数里拼。要不要把 md 也统一改成中文，你来定，但同一条规则只能有一份说明。
- T3、T4 的逐条判定（现在在 `# ---------- per entry ----------` 段）抽成 `check_entry(c, r) -> set[str]`，T1、T3、T4 共用。
- T8：先把探针帧整理成按段内秒数排好的数组 `(t, x)`，取值用 `bisect`，不用 `min`。帧号转秒数的写法和 camera_check 保持一致：`(f - START)/FPS`，START 取 `(vox.PLAN or plan).start`。
- 文件统一用 `with open(...)`。plan.json 不存在时当作 `{}`，存在但解析失败要报错，不能吞掉。
- 顺便：T3 对“正好落在场景边界上的转场”只给提示、不计入 off-beat（和 autofix 的新行为一致，见 `8f94304`），提示文字写“要对拍就挪场景边界”。**这一条会改变输出**，单独一个提交，并在提交信息里说明。

### 验收

- 除了上面说的 T3 那一条，项目 A、B 的 `out/trans_check.md` 和 `out/trans_check.json` 跟基线 diff 没有差异，退出码相同。
- 补一个最小单测 `kit/tools/songmv/test_trans_check.py`，不依赖成片和浏览器，纯数据构造：
  - 炸点只有 dip，T5 FAIL；有 flash 则 PASS
  - 没有 voxel.json，T8 PASS，detail 里写“跳过”
  - start=240，方向和镜头横移相反，T8 FAIL；同向则 PASS（这个场景和 `8f94304` 自测时用的一样）
  - dip 落在 structure 的 bridge 里，T7 PASS；落在 verse 里则 FAIL
- `python -m pytest kit/tools/songmv/test_trans_check.py` 全绿。
- 最长的函数不超过 60 行，模块顶层只剩常量和 `main`。

## R3 camplan.py 拆出 `draft_cuts`

### 现在的问题

`draft()` 有 100 多行，返回 6 个值 `(plan, cam, notes, kinds, cuts, cut_rows)`，运镜起草和转场起草混在一起。`main()` 里写 md、写 json、`--apply` 也堆在一块。

### 改成

```python
def load_inputs(P) -> dict                    # plan / structure / timeline / lines / moves，一次读齐
def segments(inp) -> list[tuple[str,int,int]] # 场景表 → 段落 → 每 10 秒，三级回退（现在 draft 开头那段）
def label_at(inp, f) -> str

def draft_camera(inp, segs) -> tuple[list, list, set]   # (cam, notes, kinds)，含“≥3 种”的底线
def draft_cuts(inp, segs, T) -> tuple[list, list]       # (cuts, cut_rows)；T = transitions.load()

def render_md(cam, notes, kinds, cuts, cut_rows) -> str
def apply(P, plan, cam, cuts, force: bool) -> str       # 备份轮换 + 写 plan.json，返回给人看的一句话
def main(argv=None) -> int
```

`apply()` 的规则保持 `8f94304` 的行为：

- 已有 camera 且没加 `--force`：退出，并提示要 `--force`
- 已有 cuts 且没加 `--force`：只写 camera，cuts 不动，并说明一句
- 备份 `plan.before_camplan.json` 已存在时，依次写 `…1.json`、`…2.json`，不覆盖旧备份

### 验收

- 项目 A、B 跑 `camplan`、`camplan --json`、`camplan --apply`，以及有 cuts 时的 `camplan --apply --force`，四种情况都和基线一致（`out/camplan.md`、json 输出、写出的 plan.json、备份文件名都相同）。
- `draft_cuts` 可以单独调用：补一个单测，3 个场景，段落是 verse → chorus → outro，期望第 1 条是 heavy 循环里的第一个（rain），第 2 条是 dip（进尾奏）。
- `run.py` 第 12 行的帮助文字同步更新（现在只写了 camera，没写 cuts）。
