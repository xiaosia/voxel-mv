# 附录 · 常见问题和修法（体素版）

不是规则：画面出了对应的问题、或者检查脚本提示了什么时来查。后半部分是 song-mv 的通用附录。

## 体素画面专有的

- **像方块游戏截图，不像微缩模型**：场景细节不够、全画面一样清楚、颜色太饱和。加小物件（每层二三十个）、开移轴、颜色降一档饱和、近景大件换 `rbox`。见 STYLE.md「怎么让它像微缩模型」。
- **角色发灰**：后期走了 render target，角色贴图被色调映射两次。引擎的后期是拷贝帧缓冲做的，改引擎时别换成 EffectComposer 那一套。
- **角色和场景两张皮**：角色是不受光的立牌（保住立绘本身的颜色）。靠脚下软影子、`grade` 调色（整帧一起调，角色跟着场景变暗变暖）、`tint` 做小差别、场景主光方向和立绘一致（左上前方）来融合。场景压暗了角色还亮着，就是只调了灯没调色。
- **脚陷进地里、鞋底被砖挡住（V2）**：地面没 `addGround`；角色站在台阶边缘、草丛、栏杆后面；立牌离前景物体太近。挪开半格，或者把那块砖降低；故意藏的写进 `occlude`。
- **飘在空中（V2）**：`play` 给的 y 比地面高太多。给个大概的 y 就行，引擎在名义高度上下 0.45 之内找地面；真的在空中（飞、跳、坐在鲸背上）用 `snap: false`。
- **走路打滑（V3）**：动作轨在走，代码里没让角色移动，或者移动速度不对。走 0.8 世界单位/拍，跑 3.2/拍；朝左走记得 `flip: true`，方向和位移要一致。镜头跟拍时角色也要真的移动。
- **特写发糊（V4）**：半分辨率素材撑不起占满画面的特写。退到中景，或者换 4 倍原图，或者用表情符号、光效、动作让情绪出来，不靠推脸。
- **七个人同框卡、显存爆**：`extra_actions` 只写用得到的动作；人多的镜头用更远的景别。
- **转场关报没登记的换场**：常见原因是特写里角色占满画面，一拍换一个大姿势，画面变化面积超过 40%。拉远一点，或者让这个变化落在已经登记的转场里；真想要的写进 `incamera`。
- **动作关量不出动作**：帧图里关键点几乎不动的动作（仰望、抱着看、祈祷）进了 `subtle`，动作关看不见。旁边加一个幅度大的动作（伸手、鞠躬、转身、走两步），或者推近镜头。
- **坏帧（V5）**：Gemini 的 `run_side` 第 3–5 帧头部跳动（Gemini 只走不跑）；Gemini `sleep`、Qwen `sit_idle` 第 4 帧被格子边切到，只用前 3 帧（动作轨里 `{to: 2}`）。

- **成片里有大片死黑（V6）**：先查方块最多的 InstancedMesh。`setColorAt` 只给用到的下标设了颜色，没用到的槽位是单位矩阵、停在原点，颜色是黑的——会在画面里渲染成纯黑方块或黑面。填完数组后把剩下的槽位藏掉：
  ```js
  for (let i = used; i < n; i++) R.setInst(im, i, 0, -80, 0, 0, 0, 0);
  done(im);
  ```
  第二类是深色材质掉进阴影（深紫的墙、音箱、地板背面）。把基色抬亮两档，再补一盏 0.4–0.6 的低强度方向光。按 `voxel_check.md` 里死黑帧的秒数去截那一帧，就能看出是哪块。
- **voxel 光爆转场登记了，T1 却说看不出**：强发光转场有好几帧整屏一样亮，降采样到 160×90 后帧差被抹平，`peak` 上不去。两条路：把进出两个镜头的构图、色温、机位拉开（前一个镜头先暗下来、后一个镜头换一个景别），或者干脆把这一下做成拍点硬切 `{"mode": 0, "kind": "cut", "len": 2}`——引擎不做混合、两帧内切，T2 允许硬切 ≤30%。硬切是拍点上的强变化，不是"退回淡入淡出"；但别把全片的转场都换成它。

- **长片很闷（场景关能过，看着还是单调）**：场景换了，但每个场景的拍法一样（同样的中景、同样的慢推、同样的能量）。回到 TREATMENT 的场景表，给每个场景定一个「收 / 放 / 反差 / 高潮」，收的场景用远景、慢、少；放的场景用近景、快剪、粒子和光一起炸；桥段换视角（俯拍、主观镜头、缩小到更小的世界）。接触表从头扫到尾，应该看得出几次明显的变化。
- **整片一个调子（调色关 L3 / L4 / L5 没过）**：每个场景都换了颜色，但都是中等亮度、低饱和，没有一段真的暗或真的亮。看 `out/grade_check.md` 的每段色调表：收着的段落 `exp` 压到 0.6–0.85、`sat` 降一点、偏冷；副歌 `exp` 1.05–1.15、`sat` 1.1–1.25、偏暖；桥段换方向（冷下来、去饱和、或者换成另一种颜色）。暗段同时把天空、主光也换成夜里的样子，留几处发光的窗和灯。
- **暗段看不清（调色关 L6）**：`exp` 压太低、或者场景本身就暗又再压一遍。给主体留一道亮：角色身边放一盏灯（emissive 方块 + `keyAt` 对着角色）、角色站在窗光里、或者 `exp` 回调一点、用 `shadow` 染色代替压暗。
- **场景关 C3 说颜色太像**：两个场景用了同一套天空和主光，只换了几件物件。换时间（黄昏、夜里、雨天）、换主色、或者换一个地面材质大面积不同的地点。故意首尾呼应的场景写 `same_as`，并且带一点变化回来（季节、光、人数）。

- **做一支片子要一个小时**：先看 `out/timing.md`。渲染占大头时跑 `python tools/run.py doctor` 看「显卡渲染」那一行，写着 SwiftShader / llvmpipe / software 就是在用 CPU 画，按提示改；检查没过反复整片重渲时，改用 `video --redo <场景>`；还在调节奏时用 `draft`。并行数用 `VOXEL_WORKERS` 调（显卡好、内存够可以 4–6，内存小就 2–3）。

## 通用（来自 song-mv）

这里是以前做 MV 时踩过的坑。**不是规则**：只在画面出了对应的问题、或者检查脚本提示了什么时来查。里面的数字是经验值，不是门槛。

### 画面定住了 / 太闷

- 先看是哪一层不动：镜头、环境（浪、云、粒子、光）、主体（角色或物体）。一般有两层在动就不会显得定住。
- 安静段也要慢慢动：慢推、慢摇、呼吸、头发和衣摆、星星依次亮。
- 一个画面里最好有一件随时间展开的事（星星一颗颗亮、烟花开了又落、人回头），这比到处加抖动有用。
- 角色停在一个姿势超过一两拍，加次级动作（呼吸、眨眼、衣摆）或镜头运动接上。

### 画面太闹 / 没有呼吸

- 不是所有东西都要跟拍。挑一两样主要元素跟拍，其余保持慢速的持续运动。
- 安静段减少元素、放慢速度、降低对比，把力气留给 drop。
- 拟声字、闪白、震屏只给真正重的时刻。

### 看不出跟着音乐

可以试：拍上的缩放脉冲或位移弹跳、元素依次点亮、分格在拍上弹入、颜色在小节线上换、角色的点头 / 跺脚 / 手势落在拍上、hit 上的震屏或闪光（强度按归一化的 `strength`）。不同元素用不同方式响应，比所有东西一起跳好看。

### 角色站着不动 / act_check 没过

- **先排动作再写镜头。** 每句先问"这一句他在做什么"，写成动词（伸手、转身、迈步、抬头指、跳、抱、举起、甩开），排进 `ACTIONS.json`。只写"站在船上""看着远方"的镜头最容易变成站桩。
- **这些不算动作**：呼吸和 `sin(t)` 式的 idle 晃动、只转头或只眨眼、镜头推拉、角色整体平移。它们可以保留做底子，但上面要有真的动作。
- **让姿势在拍上换**：关键姿势的时间取 `beat_times`，每 1–2 拍换一个姿势，中间缓动；走路的周期按拍位（一拍一步）算。打击乐 hit 上可以叠一个反应（缩身、回头），那是合拍度之外的加分。
- 镜头里角色很小（身高 < 画面 12%）时不检查；但如果全片角色大多很小，观众也看不出他在演，考虑给几个近景。
- 只看到红块（2 小节没动作）：在那段加一个动作；只看到灰块（连续静止拍）：把一个长的静止姿势拆成两三个姿势；合拍度低：看是不是关键帧时间是手写的秒数，或者动作全靠 `sin` 驱动。
- 真的需要静止（结尾定格看烟花、闭眼的一瞬），写进 `holds`，写清理由。

### 动作别扭

- 四肢脱节、反关节、忽长忽短；脚浮空或陷地；重心不在支撑脚上方。
- 走路：手脚交替（左手配右脚），身体朝前倾，脸和身体朝向一致，步幅不超过腿长。
- 常见的僵姿势：双臂垂在身前不知道在干什么、身体笔直只有腿在动、双腿分得像圆规、头和身体朝向打架、手臂像插上去的棍子。
- 好姿势：剪影一眼能认出在做什么，重心稳，手的动作有含义，身体有一点倾斜或扭转。
- 动作的重点（落地、举手、回头）放在拍点上。
- 难画的动作可以换：拥抱 → 两只手慢慢靠近；奔跑 → 中景只拍上半身加速度线和飘动的头发。

### 转场单调 / 生硬

灵感（不是清单）：形状匹配（圆月变瞳孔）、顺着动作方向甩镜、镜头穿过物体、用画面元素擦除（浪、光束、披风）、圈入圈出、网点溶解、重拍上闪白硬切、翻页、推进到细节里出现下一个场景、拉远之后变成另一个画面的一部分。

- 不需要每次换句都有转场。几句共用一个场景、一镜到底、在镜头内部换景，都是好办法。
- 力度跟能量走：安静段慢溶慢推，重的地方重转场。
- 关键帧落在拍点或小节线上，转场要短，拖进下一句会让那句显得不准。

### trans_check 没过

- **T1 有没登记的换场**：去那一秒看。真是换场就登记（多半是 `incamera`：天空换色、分格弹入、镜头内切到远景），顺手检查它是不是落在拍上；不是你想要的跳变（比如某个图层突然出现），就让它渐变或者落到拍上再登记。
- **T1 登记了但看不出**：这次换场太弱，观众感觉不到。加大变化面积（整幅换色、闪白、镜头明显移动），或者干脆不算转场、删掉这条。drop 上看不出最常见：drop 应该是全片最大的一次变化。体素/光爆转场因为中间几帧一样亮，会被降采样抹平，见上面"voxel 光爆转场"那条。
- **T2 种类太少**：按运动方式换，而不是换颜色。可以从画面里的东西出发：浪擦过去、光束扫过去、烟花炸开当闪白、月亮圈入。
- **T3 不在拍上**：关键帧时间直接取 `beat_times` / `bar_times` / `hits` 里的值，不要手写秒数；视觉冲击提前 1 帧也算在拍上。
- **T4 太长**：长溶解拆成"慢推 + 短溶解"；一个转场跨了两句歌词，说明它拖进了下一句，缩短或者挪到句首。

### 歌词画得太字面 / 画面用字解释意思

- 不必每个名词都画出来。一个贯穿的场景、一个反复出现的物件，往往比逐字插图更动人。
- 抽象词需要画面时，用具体的东西表达（时光 → 翻转的沙漏），但也可以只用光、颜色和镜头运动表达。
- 不要立路牌、标签、漂浮的概念词。

### 字幕和字

经验值：1080p 下字幕字高约 50 px 以上才看得清，拟声字更大、粗描边、有倾斜和弹入。字幕不要挡脸。

### check.py 提示怎么看

| 提示 | 意思 | 先想想 |
|---|---|---|
| `STILL` | 这句画面变化很小 | 是不是真的定住了？是有意的静止就保留，但不能定格 |
| `OFFBEAT` / beat lift 低 | 拍上的变化不比拍之间大 | 是不是有一直高速运动的元素（大雨、快速平移）把拍之间的变化抬高了？降速往往比加脉冲更好。卡在 hit 上的事件如果 hit 不在拍上，也会拉低这个数，这是设计选择可以保留 |
| hits without reaction | hit 时刻没有明显变化 | 这个 hit 重不重要？重要就给它一个画面事件 |
| 转场相关 | 转场样子少、不在拍上 | 页面登记了 `window.TRANSITIONS` 时，check.py 不再评转场，以 trans_check.md 为准；没登记时它只能粗猜（翻页、旋转会被归进 flash） |

### 技术坑

- 字幕字体是整套的 ZCOOL KuaiLe（vendor/zcool-kuaile），任何中文都有；换字体时 READY 之前要 `await document.fonts.load(...)`。
- 在页面里量物体位置、做射线检测时，打开项目要带 `?export=1`，并且把 `render(t)` 和检测放进**同一个** `page.evaluate`。不带 `export=1` 时页面跑的是预览循环，两次调用之间会从头重渲染，镜头和角色状态全被重置，量出来的永远是片头位置。
- `run.py still` 不会清空 `out/chk/`，看图时认准文件名里的时间。
- 浏览器预览（`python -m http.server`）和导出用的是同一份代码；预览正常、导出出错时看 run.py 打印的 `[page]` 报错。
